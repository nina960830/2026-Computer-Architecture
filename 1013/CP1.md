## 1. 本次目標

用 C 寫出 AVG 的參考實作 `rd = floor((rs1 + rs2) / 2)`，並設計 10 組測資（含邊界值）作為後續 RV32IM 與自訂指令版本的「標準答案」。

## 2. 設計內容

### 2.1 函式設計

```c
static int32_t avg_floor(int32_t rs1, int32_t rs2)
{
    int64_t sum    = (int64_t)rs1 + (int64_t)rs2;   // 33-bit 中間值
    int64_t result = sum / 2;                       // 向 0 截斷
    if (sum < 0 && (sum % 2) != 0) {                // 負奇數補正
        --result;
    }
    return (int32_t)result;
}
```

| 設計決定 | 理由 |
|---|---|
| 中間值用 `int64_t` | `INT_MAX + INT_MAX = 2³²−2`，32-bit 存不下；先轉型再相加才不會有 UB |
| 迴圈外不做飽和 | 平均值必介於兩運算元之間，結果一定落在 `int32` 內（見 §2.3） |
| `sum < 0 && sum % 2` 補 1 | C 的 `/` 向 0 截斷，`−7/2 = −3`，但規格要 `floor = −4` |
| `(int32_t)result` 轉型安全 | `result ∈ [−2³¹, 2³¹−1]`，不會截掉有效位 |
| `main` 只負責 I/O | 邏輯與輸入輸出分離，方便手動輸入與之後接測試程式 |

### 2.2 測資設計

10 組不是隨機挑的，每一組對應一種「容易寫錯的分支」：

| # | 類別 | 想抓的錯誤 |
|---|---|---|
| 1 | 正數、奇和 | `floor` 有沒有做（`15/2 = 7.5 → 7`） |
| 2 | 負數、奇和 | **C 截斷錯誤**（`−7/2` 應為 `−4`，截斷會得 `−3`） |
| 3 | 正數 + 0 | 一般路徑 |
| 4 | 負數 + 0、奇和 | `−0.5 → −1`，最容易誤以為是 0 |
| 5 | 正負相消 | 和為 0 的邊界 |
| 6 | `INT_MAX` + `INT_MAX` | **中間值溢位**（需 33-bit） |
| 7 | `INT_MIN` + `INT_MIN` | 下界溢位 |
| 8 | `INT_MAX` + `INT_MIN` | 極端值相消（和為 `−1`） |
| 9 | 偶和、同值 | 不需要補正的路徑 |
| 10 | 負數、奇和（不同絕對值） | 再一組截斷測試，避免只硬編一組 |

§6.1 指定的三組必測 `(7,8)`、`(−3,−4)`、`(2147483647,2147483647)` 都在其中（#1、#2、#6）。

### 2.3 結果範圍的證明

- 最大：`(2³¹−1) + (2³¹−1) = 2³²−2`，`floor((2³²−2)/2) = 2³¹−1 = INT_MAX`
- 最小：`(−2³¹) + (−2³¹) = −2³²`，`floor(−2³²/2) = −2³¹ = INT_MIN`
- 一般：`min(a,b) ≤ floor((a+b)/2) ≤ max(a,b)`

所以需要 33-bit 的只有**中間的和**，結果本身不需要飽和、不需要旗標。

## 4. 遭遇的問題與解法

**問題：32-bit 相加會溢位，而 C 的除法語意又和規格不同。**

`avg.c` 的註解顯示作者同時處理了兩件事：

1. **溢位**：`(int32_t)rs1 + rs2` 在 `INT_MAX + INT_MAX` 時是 signed overflow，屬 UB（不是「繞回」而已，編譯器可以假設它不會發生）。解法是**先轉成 `int64_t` 再加**，讓中間值真的是 33-bit。
2. **截斷方向**：C 的 `/` 向 0 截斷，規格要 floor。解法是對「和為負且為奇數」補 1。

兩者必須**同時**做：只修溢位，`(−3,−4)` 還是會錯；只修截斷，`INT_MAX` 還是會錯。

## 5. 白話說明（200 字內）

AVG 就是「兩個數的平均，小數點以下無條件捨去」。

寫成程式時有兩個陷阱。第一，兩個 32 位數相加可能超過 32 位能表示的範圍，所以要先用更大的位數（64 位）把和算出來。第二，C 語言的整數除法遇到負數時是「往 0 靠」，但我們要「往下靠」——例如 −7 除以 2，C 給你 −3，正確答案卻是 −3.5 往下取整的 −4，所以負的奇數要再減 1。

這兩件事都處理好，平均就只是「加起來、除以二」而已。測資裡特地放了 `2147483647`（32 位最大整數）和幾個負奇數，就是為了確認這兩個陷阱真的被處理掉了。
